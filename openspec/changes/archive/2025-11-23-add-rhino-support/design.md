# 增加 Rhino (.3dm) 支持 - Design

## Context
Rhino (.3dm) 是基于 OpenNURBS 标准的 CAD 文件格式。虽然官方提供了 C++ SDK 和 .NET SDK，但 Python 绑定 `rhino3dm` 因跨平台 GUI 依赖问题，不支持直接提取预览图。
然而，Rhino 文件通常在头部非压缩区域嵌入了标准格式（BMP 或 PNG）的预览图。

## Goals
- 支持扫描并索引 `.3dm` 文件。
- **零依赖**：不依赖 Rhino 软件安装，不引入庞大的第三方库（如 `rhino3dm` 或 `trimesh`）。
- **高性能**：通过只读取文件头（前 128KB）进行二进制特征匹配，快速提取预览图。

## Decisions

### Decision 1: 二进制特征扫描提取预览图
- **方案**：不解析完整的 OpenNURBS 结构，而是直接在文件二进制流的前 128KB 中搜索图像文件头特征（Magic Bytes）。
    - BMP 特征：`BM` (0x42 0x4D) + 文件大小校验。
    - PNG 特征：`\x89PNG\r\n\x1a\n`。
- **理由**：
    - 速度极快（毫秒级），无需加载数百 MB 的模型数据。
    - 纯 Python 标准库实现，跨平台（Windows/Linux/Docker）。
    - 经调研，绝大多数 Rhino 保存的文件都以此方式嵌入了预览图。

### Decision 2: 存储策略
- 数据库记录：
    - `path`: 存储 `.3dm` 文件的原始绝对路径。
    - `file_format`: 存储为 `3dm`，以便区分和特定处理。
- 特征计算（CLIP）：
    - 在计算 CLIP 特征向量时，内存中提取预览图并传递给模型，不生成中间临时文件（除非用于调试）。

### Decision 3: 前端展示
- 前端请求图片 URL（如 `/api/image/123/thumbnail`）时，后端检测到该记录是 `3dm` 格式，实时提取预览图并返回 `image/jpeg` 或 `image/png` 流。
- 前端无需特殊修改，只需像展示普通图片一样展示即可。

## Risks / Trade-offs
- **风险**：极少数通过特殊方式保存或被加密的 .3dm 文件可能无法提取预览图。
    - **缓解**：提取失败时，使用默认的“占位图标”或记录错误日志，不中断扫描流程。
- **风险**：误判二进制特征（如文件描述文本中包含 "BM"）。
    - **缓解**：增加 BMP/PNG 头部结构校验（如检查文件大小字段是否合理），不仅仅匹配 Magic Bytes。

## Open Questions
- 是否存在无预览图的 .3dm 文件？（存在，如果是“仅保存几何体”或旧版本。处理方式：跳过或仅作为普通文件索引但不显示图）-> 决定：作为普通文件索引，显示默认 3D 图标。
