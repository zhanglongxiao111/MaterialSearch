# 提案：集成库类型选择功能

## 概述

完成双数据库架构的前后端集成，使用户能够通过界面区分"永久素材库"和"临时项目库"，实现完整的素材分类管理工作流。

## 问题陈述

当前系统已实现双数据库架构的后端基础（`add-project-database-architecture` 提案），但**扫描、搜索、上传功能尚未与库类型选择集成**，导致：

1. **无法指定扫描目标**：扫描时不能选择存入永久库还是项目库
2. **搜索范围不明确**：无法限定在永久库或特定项目库内搜索
3. **上传目标固定**：上传图片时无法选择目标库
4. **前端缺少项目管理**：没有创建项目、切换项目、查看项目列表的界面
5. **用户体验割裂**：后端已支持双库，但前端仍按单库模式操作

## 目标用户

建筑设计事务所的设计师和管理员：
- 需要将**临时项目文件**和**精选参考素材**分开管理
- 希望在项目内快速搜索（100 张图片，<1 秒）
- 项目完成后归档精选内容到永久库

## 解决方案

在现有双数据库架构基础上，添加库类型选择的前后端集成：

### 1. 扫描集成
- 扫描前选择目标库（永久库 / 新建项目 / 现有项目）
- 根据选择将图片存入对应数据库
- 自动计算并存储图片属性（宽高比等）

### 2. 搜索集成
- 搜索时选择范围（永久库 / 当前项目 / 所有库）
- 修改 `search.py` 支持 `library_type` 和 `project_id` 参数
- 结果中标注来源库

### 3. 上传集成
- 上传时选择目标库
- API 添加 `target` 参数（`permanent` / `proj_xxx`）

### 4. 前端界面
- 添加项目管理面板（创建、列表、切换）
- 搜索/扫描/上传时显示库选择器
- 状态栏显示当前活动库

## 成功指标

- ✅ 扫描时可选择目标库，图片正确存入对应数据库
- ✅ 搜索时可指定范围，返回结果仅来自目标库
- ✅ 前端可创建项目、切换当前活动项目
- ✅ 项目内搜索响应时间 < 1 秒（100 张图）
- ✅ 永久库搜索响应时间 < 3 秒（1 万张图）

## 依赖关系

**前置依赖**：
- ✅ `add-project-database-architecture`：双数据库架构已实现

**阻塞的功能**：
- 建筑设计行业定制化完整工作流
- 智能去重功能（需要明确去重范围）
- AI Agent 集成（需要明确操作目标库）

## 不包含的内容

本提案**不包括**：
- 跨库智能去重（Phase 2 功能）
- 批量归档界面（使用 API 即可）
- 项目协作和权限管理
- 视频素材的库类型支持（图片优先）

## 风险评估

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 前端状态管理复杂度增加 | 中 | 使用 localStorage 持久化当前项目 |

| 用户学习成本 | 中 | 提供默认值，简化常用场景 |

- ✅ 未指定库类型时默认使用永久库
- ✅ 单库模式用户无感知变化
